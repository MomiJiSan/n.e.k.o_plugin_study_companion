# v0.2.6 认知引擎 V2 发布说明（候选）

## 发布定位

本版本收口认知引擎 V2 的正确性边界，并加入 V2.1 的保持检查闭环。它不是
V3，不提供跨学科策略个性化，也不会公开概率、智力、注意力或学习风格判断。
唯一允许启用的主动错因仍是链式法则的 `omit_inner_derivative`。

真实 Shadow 放行阶段按产品决定跳过；这只取消等待阶段，不降低默认关闭、
故障隔离、版本校验、迁移和回滚要求。

## 主要变化

- 使用认知专用事实根和单一 reducer，使迟到 extraction、同秒答题和重建结果
  保持确定性；旧 transfer 不再覆盖较新的 relapse。
- Reader 在读取时叠加用户控制。短期 suppress 最长 24 小时并可自动到期；
  delete cutoff 永久保留，restore 不会复活删除前的事实。
- Coach Planner 是选题和最终计划的唯一所有者。认知引擎只提交候选，不会在
  Planner 决定后篡改题目计划。
- 正常答题事务与认知处理通过 reference-only outbox 隔离。认知内部失败不会
  丢失已验证的普通答题、FSRS、Mastery 或错题更新。
- 新增 MonitoringEpisode、LearningObligation、带 lease/CAS 的 claim，以及
  保持检查结果事实。通过七天窗口仍未完成时回到
  `provisionally_resolved` 并重新提交 transfer 候选，不会自动算作 resolved 或
  relapse。
- 保持检查只在延迟、独立、无提示、版本兼容且 evaluator 认证正确时推进
  `monitored -> resolved`；同一错因再次出现才增加 relapse。

## 默认配置与启用条件

发布配置必须保持：

```toml
[cognitive]
projection_enabled = false
read_mode = "off"
intent_policy = "off"
ui_enabled = false
retention_enabled = false
version_set = "cognitive-v2.1-1"
```

V2.0 主动干预要求 projection、`read_mode="active"` 和
`intent_policy="on"` 同时成立。V2.1 还要求 `retention_enabled=true`。
任一版本组合未知、投影积压、episode 过期或 obligation 冲突时，交付路径回退
普通 QuestionPlan。

## 升级与数据兼容

- 从 v0.2.5 打开数据库时只执行 additive migration；旧表和旧列不会删除。
- 旧 `status` 继续作为兼容派生值，旧 `user_override` 列继续保留，但不再作为
  新投影的判断真相源。
- 旧 `cognitive-v1` 投影仍可读和回滚；新 reducer 写入独立的
  `cognitive-v2.1-1` 投影。
- episode、obligation、claim、satisfaction、认知 outbox 和 delete cutoff 均为
  SQLite 持久状态，应用重启不会隐式清空。
- Web 与 Electron 均由宿主加载同一个 `surfaces/study_panel.tsx`；不维护认知
  UI 的平台分叉版本。

升级前仍建议备份数据库。若升级被中断，可使用原数据库备份恢复；不要手工删除
delete cutoff。

## 回滚

- 关闭 `retention_enabled`：停止产生和消费新的保持义务。
- 关闭 intent：继续保存普通答题和可用 evidence，但不交付认知题。
- 关闭全部认知开关：普通学习行为与 v0.2.5 等价，仅保留不参与决策的 additive
  存储结构。
- outbox 积压不会阻塞普通答题；未知版本不会被 worker 领取或写入新投影。
- 回滚代码也必须尊重永久 delete cutoff，禁止恢复删除前的认知事实。

## 发布边界

本版本不修改 N.E.K.O 核心仓库，不让 retention 覆盖 FSRS 安排，不扩展新的
Active 学科或错因，不建设通用工作流引擎或全局事件总线。
